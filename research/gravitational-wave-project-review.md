# 引力波可视化项目比较与改造方案

调研日期：2026年10月23日。

建议采用独立浏览器界面，组合 binaryBHexp 的轨道与自旋表达、Cardiff Waveform Fitter 的真实信号对照交互，以及 PyCBC 的波形和探测器响应计算。后续用 GWSurrogate 扩展进动。这样可以从直观的双黑洞动画，逐步连接到本项目已有的形成渠道代理模型与选择效应分析。

本次依据官方文档和选定源码进行比较，未运行各项目的完整程序或性能测试。源码快照位于 research/snapshots；已取得元数据的仓库记录了完整提交号。网页说明和默认分支内容可能继续更新。

## 源码核查带来的修改依据

**显示速度与物理时间要分别管理。** binaryBHexp 的说明明确采用每轨道固定帧数，让临近并合过程慢放。这个设计有利于观察，但屏幕上的动画时间不等同于物理时间。我们应保留一条以秒表示的物理时间轴，播放倍率只改变游标推进速度。[项目说明](https://vijayvarma392.github.io/binaryBHexp/)

**有波形曲线不代表数值已按物理单位校准。** MdKasif0 项目在同一个引擎中，对频率乘45、相位推进乘4、轨道衰减乘0.08；应变幅度分母固定为100，振铃相位又使用显示频率除40。源代码中的这些不同缩放使频率读数、相位演化和时间单位之间的对应关系需要重新建立。自旋在该文件中参与遗迹计算，却没有进入旋近动力学。[固定提交源码](https://github.com/MdKasif0/Gravitational-Wave-Simulation/blob/8af742055a011ffaabbc4cf176befeff7e9b116d/src/physics/GWPhysicsEngine.ts#L85)

同一实现的遗迹自旋公式，在等质量、无初始自旋时，未截断值为 `4√3×0.25−3.871×0.25²≈1.490`，随后被截到0.995。因此不能直接把这一实现当作经过验证的遗迹拟合。我们的遗迹质量、自旋和振铃应来自注明出处且经过验证的模型。[对应代码](https://github.com/MdKasif0/Gravitational-Wave-Simulation/blob/8af742055a011ffaabbc4cf176befeff7e9b116d/src/physics/GWPhysicsEngine.ts#L130)

**渲染模块可以复用，强场动力学需要单独处理。** algometrix 的 `stepBinary` 同时压缩轨道相位和径向衰减的时间尺度，值得借鉴；不过其 Peters 衰减加 Kepler 轨道属于近似，并合条件使用两显示半径之和，不能替代完整强场解。`displayRs` 的注释明确将半径振荡描述为艺术化表达。我们应让科学波形独立于这种视觉过渡。[固定提交源码](https://github.com/algometrix/blackhole-sim/blob/0ee5541ec4ffcd9ca708f37c080bf00b7f3ef6d1/src/sim/binary.ts)

**缓存波形是有效的交互优化，但要限定缩放条件。** Cardiff 的代码以65太阳质量和420 Mpc为参考，通过时间与振幅缩放实现即时反馈。固定质量比、无量纲自旋和观测方向时，可以利用真空双黑洞波形的质量尺度关系；改变质量比或自旋则需要新的波形，不能继续缩放原曲线。[固定提交源码](https://github.com/cardiffgravity/waveform-fitter/blob/87b6a9e2c2dcaf661df618506d60a76d5dc3d4fe/js/wavefit.js#L74)

## 第一版的具体范围

第一版以准圆、非进动双黑洞为对象，展示旋近、并合、振铃。优先做好轨道示意、极化响应和波形的同步，再增加昂贵的透镜渲染。

| 界面区域 | 用户操作 | 显示结果 |
|---|---|---|
| 参数区 | 改变两质量、沿轨道角动量方向的两自旋分量、距离、倾角 | 新波形及模型适用范围；超出范围时阻止计算 |
| 中央场景 | 播放、暂停、拖动时间、旋转观察相机 | 轨道示意、自旋方向、阶段标记和当前物理时间 |
| 极化示意 | 切换 h+、h× 或两者叠加 | 测试粒子环的相对形变；明确标注显示放大倍数 |
| 波形区 | 同步游标、缩放时间窗口、比较两组参数 | h+、h×，有效时间区间内的频率，后续加入探测器应变 |
| 声音区 | 开关、音量、播放速率 | 波形声化；标注归一化及变速，不能把声音音量解释为真实应变 |

观察相机默认只控制视图。物理倾角单独控制；需要“相机即观察者”模式时明确切换，避免转动镜头悄悄改变信号。

建议结构为：参数与模型配置 → Python 波形计算 → 带单位和版本的波形数据 → 浏览器统一时间轴 → 三维场景、极化图、波形及声音。前端可用 Three.js 加轻量图表；是否采用 React 取决于面板复杂度。

初始后端可选择 PyCBC 提供的 IMRPhenomD 等非进动模型，先核实实际安装的可用模型及支持范围。波形返回值包含 `t_s`、`h_plus`、`h_cross`、模型名、版本、参数、质量参考系、距离、参考频率和采样间隔。轨道数据增加独立的来源标签；不能将仅由波形相位推导的三维示意标为数值相对论轨迹。[PyCBC 示例](https://pycbc.org/pycbc/latest/html/waveform.html)

物理采样率不依赖浏览器帧率。绘图降采样、音频重采样与物理信号缓存分开处理，采用适当抗混叠方法。参数修改后先计算并缓存，再播放；只有通过精度检查的参数区间才启用模板插值。Windows 环境的依赖安装与运行速度留待实际小样本试运行确认。

## 后续扩展

**第二步接入 GW150914 真实数据。** 使用 GWOSC 的 strain 数据与公开后验产品，提供模板叠加、H1/L1 探测器投影、噪声功率谱和匹配度。模板和观测数据使用一致的滤波与白化过程，清楚区分原始应变、处理后信号和模型。默认事件配置从同一条联合后验样本取值，避免拼接独立中位数。当前工作区的精简后验缺少完整外禀参数，需要补充原始公开后验。[GWOSC 教程](https://gwosc.org/tutorials/)

**第三步加入进动。** 通过 GWSurrogate 支持的模型返回模式波形与可用动力学信息。NRSur7dq4 的训练质量比范围至4，NRHybSur3dq8 面向非进动、质量比至8；这些数字不能代替各模型完整的自旋、频率和时长边界。固定具体模型版本后，再设计滑块上下限。[GWSurrogate](https://github.com/sxs-collaboration/gwsurrogate)

**第四步连接形成渠道与选择效应。** 从本项目的偏对齐和各向同性代理分量抽样，展示它们可能产生的波形集合；进一步展示探测前后参数分布如何变化。单个事件的动画不能判定其形成渠道。波形与信噪比可以帮助解释选择偏好，正式选择函数仍需与观测运行和搜索阈值匹配的注入数据。

## 接入现有数据需要的转换

| 现有约定或缺口 | 接入要求 |
|---|---|
| 现有群体模型 `q=m2/m1≤1` | GWSurrogate 使用大质量除小质量，接口处转换为 `1/q`，并保持对应自旋的对象标识 |
| 后验质量为源参考系质量 | 观测波形使用探测器参考系质量 `m_det=(1+z)m_source`；如由红移计算光度距离，记录宇宙学假设 |
| 精简后验有自旋幅度与倾角余弦 | 不足以唯一指定进动波形；需补充方位角、参考频率及坐标约定 |
| 精简后验缺少完整天空位置、倾角和极化角等参数 | 完整探测器信号应读取原始联合后验；额外假设只能作为演示配置 |
| 现有两分量只是形成渠道代理 | 标签继续使用偏对齐和各向同性，避免直接改成已确认的孤立演化或动力学形成 |

## 实施时的验收标准

1. 固定探测器参考系质量及其余参数，距离加倍，应变振幅减半。
2. 固定质量比、无量纲自旋、方向和距离，对应无量纲阶段的时间尺度随总质量变化；频率反比变化，幅度按质量尺度变化。
3. 仅在准圆、主导四极旋近适用区间，检查引力波频率约为轨道频率两倍。并合后不继续显示虚构的双体轨道频率。
4. 用后端原始输出检验前端重采样和插值的误差；改变绘图帧率后物理波形及并合时刻保持一致。
5. 先测试无噪声注入的参数回收，再比较真实事件；使用一致的 PSD、频带、时间与相位对齐定义计算匹配度。
6. 同一参数在两种适用波形模型下比较，单独展示模型差异；不得用一条曲线的视觉吻合替代参数估计与不确定性分析。

第一阶段的完成标志是：一组经过检查的波形，驱动可拖动的同步动画与极化图，并能导出参数和数据。第二阶段再用真实事件评估模型与噪声影响，最终与现有群体推断工具衔接。
